# Risk register

Seeded: 2026-10-31, Phase 0 gate. Columns: Risk, Likelihood, Impact, Mitigation, Owner. Owners are "Project lead" (solo founder + opencode) until roles exist; review at each phase gate.

| Risk | Likelihood | Impact | Mitigation | Owner |
|---|---|---|---|---|
| A misroute sends a question down the wrong path: the question fails before either path starts. | Medium | High | Router evaluated as its own component (ADR-0001): labelled router questions in the labelled set from day one, >=95% accuracy gate, prefer abstain on low confidence. Router mechanism re-compared in Phase 8 with failed-route analysis. | Project lead |
| Synthetic dev data is too clean: the system passes evals, then fails on real customer data. | Medium | High | Dev data is deliberately messy by decision: messy schema + contradictory policy docs, versioned so failures are reproducible (Decision 3). Realism re-check before any real-customer pilot (before Phase 5). | Project lead |
| Demo objection: "Can it read our Notion?" - prospect expects a source outside the MVP list. | High | Medium | MVP sources are fixed (Postgres/Supabase + PDF/DOCX/CSV, everything else deferred). Scripted demo answer that names what is in scope and what is deferred. Log every occurrence; feed the source-priority decision after Phase 5. | Project lead |
| A hybrid question gets answered from only one half; synthesis quality shortfall. | Medium | High | Synthesis step is an explicit ADR-0001 consequence. Labelled hybrid questions included in the labelled set; abstain rate tracked separately; each path built and tested independently so failures localise. | Project lead |
| A follow-up rewrite garbles the intent and the persona gets a confident wrong answer. | Medium | High | The rewritten standalone question is part of the answer evidence so mistakes are visible; ambiguous rewrites abstain instead of answering (AC-FUP-1/AC-FUP-3). The rewrite step is evaluated as its own component when built. | Project lead |
| PII in result rows reaches the model. | Medium | High | ADR-0003 tiered exposure: schema only for SQL generation, capped rows for synthesis, no samples by default; row-level tables rendered from the DB result and not read by the model (Phase 5 confirmation); the Admin's exposed-table selection bounds what can enter a query (AC-ASK-4/AC-ASK-5). | Project lead |
| The 50-table limit is unvalidated; real workspaces may or may not fit it. | Medium | Medium | Treat 50 as provisional until pilot data exists: measure table counts from the synthetic dev set first, then real workspaces (from Phase 5); a workspace needing more re-opens the limit via a new ADR instead of a hard block. | Project lead |
| CSV type inference fails on messy real-world CSVs. | High | Medium | ADR-0002 consequence: the type-inference step fails the upload loudly with per-column info and serves no partial table (AC-CSV-2); messy data is what the dev dataset exercises by design. | Project lead |
| Founders distrust pasting a connection string (security objection, sibling of the Notion objection). | Medium | Medium | Connect step demands a read-only role and says what the workspace can and cannot see (AC-DB-1/AC-DB-4); evidence story leans on HG2 (0 writes/DDL). Log objections to feed objection-handling assets. | Project lead |
| RLS with connection pooling: a pooled connection can carry stale tenant context between app-data statements and CSV queries. | Medium | High | Tenant scope is bound per work unit and HG1 isolation tests (docs/architecture/enforcement-and-failures.md) run against the pooled setup before serving questions; the pooler's shape is HLD OQ-4 (ADR-0010 provisional row). | Project lead |
| Customer DB load: the live query path can strain the customer database. | Medium | Medium | One read-only connection per question, bounded by the 30 s timeout and the 10,000-row cap (ADR-0006 + decision 7 + PRD limits table); no bursts; the abstain path keeps slow customer infra from degrading our surface (AC-ABS-3). | Project lead |
| LLM provider outage stalls every question (single provider by ADR-0009). | Medium | High | Typed SSE error event, no silent hang (docs/architecture/enforcement-and-failures.md); reliability is a Phase 8 bake-off criterion (decision 6); retry/fallback pattern resolution tracked as HLD OQ-5. | Project lead |
| Prompt changes after a provider model update silently degrade quality. | Medium | High | Version the prompts/questions so the labelled evals re-run (router >=95%, T1-T4 thresholds in docs/phase-0/scope.md) before serving after any provider/model bump; Phase 8 owns provider choice via decision-log entry, never by editing ADR-0009. | Project lead |
| "Provisional" stack items drift into de facto decisions without owner phases. | Medium | Medium | ADR-0010's provisional table is the SSOT; AGENTS Phase 2 rule keeps "provisional + owner phase" markers in every architecture doc; phase-gate reviews check for drift; unset owner phases live in docs/architecture/HLD.md Open questions. | Project lead |
| Windows PowerShell vs Unix CI shell skew makes the one gate behave differently across hosts (recipes parse under pwsh locally and sh in CI). | Medium | High | Recipes avoid shell operators and rely on just's windows-shell setting (ADR-0012); the full gate runs locally before every report, and CI/local parity is proven when the CI task lands. | Project lead |
| Generated artefacts (generated.ts, .env.example) go stale or get hand-edited, breaking gate tests. | Medium | Low | Freshness tests fail loudly and name the regeneration recipe; regeneration is wired into the workflow (ADR-0014); hand edits are on the Never list in AGENTS.md. | Project lead |
| Docker unavailability on the dev machine makes the testcontainers integration harness unrunnable, so the local gate cannot go green for integration tests. | Medium | Medium | Docker availability is verified (docker info) before the integration harness task starts; if absent, install or record a fallback harness decision in the decision log before the API work begins. | Project lead |
